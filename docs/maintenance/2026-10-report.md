## Empfehlungen

1. TypeScript 7.0.2 ist laut npm die aktuelle Latest-Version. In der Probe liefen `npx tsc --noEmit` und `npm run build` mit Exit 0. `npm run lint` endete mit Exit 2. Die Meldung war: typescript-eslint unterstützt TS 7.0 nicht. Das Projekt bleibt deshalb auf 6.0.3. Ein neuer Versuch lohnt sich, sobald typescript-eslint TypeScript 7 unterstützt.

2. ESLint 10.13.0 wurde probeweise installiert. Lint, Typprüfung und Build liefen mit Exit 0 durch, inklusive derselben bestehenden Bild-Warnung. Drei Plugins, die `eslint-config-next` 16.4.2 mitbringt, nennen ESLint 10 nicht als unterstützte Peer-Version: `eslint-plugin-import` 2.32.0, `eslint-plugin-jsx-a11y` 6.10.2 und `eslint-plugin-react` 7.37.5. Das sind jeweils die neuesten Veröffentlichungen. npm hat die Peer-Abhängigkeit beim Installieren überschrieben. Der Wechsel wurde deshalb nicht behalten. Beim Installieren von ESLint 9.39.5 warnt npm, dass diese Version nicht mehr unterstützt wird. Sobald `eslint-config-next` Plugins mit ESLint-10-Unterstützung liefert, sollte der Wechsel nachgeholt werden. ESLint 10 verlangt Node `^20.19.0`, `^22.13.0` oder ab Version 24.

3. Die `braces`-Kette weiter beobachten. Ein Update ist erst sinnvoll, wenn `braces`, `micromatch` oder `@next/eslint-plugin-next` eine gepatchte Version veröffentlichen. `eslint-config-next` sollte dabei auf der Next-16-Linie bleiben.

4. In den Vercel-Projekteinstellungen die Node-Version prüfen. Next.js 16 verlangt Node 20.9.0 oder neuer. `@types/node` 26.6.5 beschreibt die APIs von Node 26. Diese Prüfung lief auf Node 22.23.3. Die Typen ändern die Laufzeit auf Vercel nicht. Neuer Code sollte nur APIs nutzen, die die dort eingestellte Node-Version wirklich hat.

5. Im README steht, `npm audit` solle nach der Installation 0 Schwachstellen melden. Nach diesem Lauf bleiben 5 hohe Befunde in der Dev-Kette. Der Satz sollte angepasst werden, sonst wirkt ein späteres Audit wie ein Rückschritt.

6. Eine kleine automatische Testsuite wäre der größte Hebel für die nächsten Monate. Ohne Tests bleibt die monatliche Prüfung bei Installation, Lint, Typen und Produktionsbuild.

Die Bild-Warnung in der Galerie ist eine eigene Produktentscheidung. Ein Wechsel auf `next/image` würde die Bildoptimierung von Next nutzen, die in diesem Lauf gepatcht wurde. Das war nicht Teil der Wartung.

## Risiken

- TypeScript 6 ist ein Major-Wechsel. Lint, Typprüfung und Build sind auf dem endgültigen Stand grün. Die Obergrenze `~6.0.3` hält das Projekt unter der Grenze von typescript-eslint.
- `@types/node` 26 liegt vor der Node-Version dieser Prüfungsumgebung (22.23.3). Für den vorhandenen Code (`path` und `url` in `next.config.ts`) war das unproblematisch.
- Ohne automatische Tests bleibt das Verhalten im Browser ungeprüft. Der Build hat die statischen Seiten erzeugt.
- Fünf hohe Audit-Befunde bleiben in den ESLint-Werkzeugen. Der Produktionscode zieht diese Pakete nicht.
- ESLint 9.39.5 ist vom Hersteller als nicht mehr unterstützt markiert. Der Verbleib gilt, bis die Next-Lint-Plugins ESLint 10 führen.
- Das Lockfile ist größer, weil optionale Binärpakete für andere Betriebssysteme mitgeschrieben werden. Das betrifft die Installation, nicht die Seiteninhalte.
